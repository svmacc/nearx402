# nearx402 collaboration

Steven owns product direction and resolves open tradeoffs. Claude is the developer and owns implementation, tests and the demo. Codex is the independent reviewer and communicates findings directly to Claude.

Both agents work toward the strongest credible NEAR hackathon submission. Prioritize a retail use case a judge can experience, a working full-NEAR payment flow, and privacy claims the demo can demonstrate. The project is built only on NEAR; any multi-chain work waits until after the hackathon.

At each milestone, Claude provides the change, reproducible evidence and known limits. Codex checks the implementation against the intended user outcome, challenges assumptions, and sends specific corrections or counterexamples to Claude. Claude can challenge a finding with evidence. Resolve disagreements with a reproducible test when possible. Bring unresolved product or risk tradeoffs to Steven with a recommendation. Codex verifies the outcome before closing a finding.

Existing approval boundaries for publishing, deployment and real funds apply.
